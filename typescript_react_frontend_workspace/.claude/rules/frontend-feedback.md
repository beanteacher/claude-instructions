# 화면 알림 기준 — 빨간 글씨·토스트·창·완료 화면 (규칙 전용)

> 사용자에게 결과·오류·확인을 알릴 때 무엇을 쓸지 정하는 기준이다. 새 화면을 만들거나 알림을 고칠 때 이 표로 고른다.
> 근거: NN/g(Indicators·Validations·Notifications, Confirmation Dialogs), IBM Carbon Notification pattern, Shopify Polaris Toast·Error messages,
> Atlassian Flag, GOV.UK Confirmation pages·Error summary, WCAG 2.2.1 Timing Adjustable (2026-11-16 정리).

---

## 1. 고르는 표

위에서부터 맞는 줄을 고른다.

| 상황 | 쓰는 것 | 사라지는가 |
|------|---------|-----------|
| 칸 입력이 틀렸다 (형식·빈 칸·겹침·틀린 비밀번호) | **칸 바로 아래 빨간 글씨** + 고치는 법. 칸이 많은 폼(주문서 등)은 폼 맨 위에 오류 요약도 둔다 | 고칠 때까지 남는다 |
| 누른 동작이 실패했다 (서버 거절·서버 오류·동시 수정, 칸이 없는 토글 실패) | **그 영역 바로 위·아래 빨간 안내** (폼이면 저장 버튼 위나 폼 맨 위, 토글이면 그 줄 아래). 토글은 원래 값으로 되돌린다 | 다시 하거나 고칠 때까지 남는다 |
| 연결 끊김처럼 잠깐 생긴 시스템 문제 (특정 영역과 상관없음) | 빨간 토스트 + [다시 시도]. **오류 토스트는 이 경우만** | 저절로 사라진다 |
| 작은 동작이 성공했고, 바뀐 결과가 화면에 보인다 (저장·추가·삭제·적용·동의 바꿈) | **검정 토스트**, 짧게 ("저장했습니다.") | 저절로 사라진다 (3초) |
| 되돌릴 수 없거나 심각한 일을 하기 전 (삭제·정지·탈퇴·저장 안 하고 나가기) | **확인 창**: 무엇이 어떻게 되는지 구체적으로, 버튼에는 결과를 쓴다 ([삭제] [탈퇴하기], "예/아니오" 금지) | 고를 때까지 남는다 |
| 누른 동작이 규칙 때문에 막혔고, 이유와 다음 할 일을 읽어야 한다 (연결된 제품이 있어 삭제 불가 등) | **안내 창** (빨강 제목 + 이유 + 할 일, 필요하면 할 일 버튼) | [확인]을 누를 때까지 남는다 |
| 바로 읽어야 하는 안내 (처음 비밀번호 바꾸라는 권유 등) | **안내 창** | [확인]을 누를 때까지 남는다 |
| 여러 단계 흐름이 끝났거나, 되돌릴 수 없는 큰 일이 끝났다 (가입·찾기·재설정·탈퇴·주문·견적 요청) | **완료 화면**: 된 일 + 다음에 일어날 일 + 다음 할 일 버튼 (번호가 있으면 번호) | 화면이다 |
| 화면 데이터를 못 불러왔거나 비었다 | **화면 안 상태 글** + [다시 시도]·링크 | 상태가 바뀔 때까지 남는다 |

## 2. 하지 않는 것

- **오류를 토스트로 띄우지 않는다.** 위 표의 "잠깐 생긴 시스템 문제"만 예외다. 토스트는 짧아서 무엇이 왜 잘못됐고 어떻게 고치는지 담지 못하고, 놓치면 다시 볼 곳이 없다.
- **꼭 알아야 할 내용을 토스트에만 싣지 않는다.** 저절로 사라지는 알림은 같은 내용을 화면 다른 곳에서도 볼 수 있을 때만 쓴다 (WCAG 2.2.1).
  예: "바꾸면 다른 기기는 로그아웃됩니다"는 폼 안 안내 문구로 미리 보여 주고, 토스트는 "비밀번호를 바꿨습니다."만.
- **작은 성공에 창을 띄우지 않는다.** 저장할 때마다 [확인]을 누르게 하면 읽지 않고 누르는 습관이 생긴다.
- **되돌릴 수 있는 평범한 동작에 확인 창을 띄우지 않는다.** 자주 뜨는 확인 창은 읽히지 않는다. 확인 창은 되돌릴 수 없는 일에만.
- **브라우저 기본 창(`window.alert`·`window.confirm`)을 쓰지 않는다.** 모양·초점·문구를 정할 수 없다. 프로젝트의 확인 창 부품을 쓴다.
- **권한 없음 같은 안내를 볼 수 없는 사람에게 띄우지 않는다.** 들어오면 안 되는 사람에게는 화면이 있다는 것도 드러내지 않는다 (없는 주소와 같은 404).

## 3. 문구

- 오류: 무엇이 안 됐는지 + 어떻게 하면 되는지. "저장하지 못했습니다. 잠시 뒤 다시 시도해 주세요." 사용자를 탓하지 않는다.
- 성공 토스트: 한 문장, "~했습니다." 무엇을 했는지만.
- 확인 창: 제목은 묻는 말("분류를 삭제할까요?"), 본문은 무엇이 사라지는지, 버튼은 결과.
- 안내 창(막힘): 제목은 짧게("삭제 불가"), 본문은 이유 + "~해 주세요".

## 4. 사용자 화면과 관리자 화면

**고르는 기준(1~3장)은 두 화면이 같다.** 다른 것은 모양뿐이다.

| | 사용자 화면 | 관리자 화면 |
|---|---|---|
| 칸 빨간 글씨 | 사용자 입력 부품의 오류 글씨 | 관리자 입력 부품의 오류 글씨 |
| 영역 빨간 안내 | 사용자 오류 글씨를 영역 위·아래에 | 관리자 오류 안내 상자 (빨간 테두리·옅은 빨강 바탕) |
| 토스트·확인 창·안내 창 | 공통 부품 하나를 같이 쓴다 | 같음 |
| 완료 화면 | 따로 뜨는 화면 틀의 결과 화면 | 관리 화면은 흐름이 짧아 거의 없다. 생기면 같은 기준 |

두 화면의 기준이 달라야 하는 경우가 생기면 이 장에 "무엇이 왜 다른지"를 한 줄씩 더하고 그 화면에만 적용한다. 지금은 없다.

## 5. 점검할 때

기존 화면을 이 기준으로 점검할 때는 항목마다 **유지 / 바꿈 + 이유**를 한 줄씩 적는다. "나머지는 기준과 같다"로 묶지 않는다.
근거가 "설계서·기존 코드가 그래서"뿐인 항목은 기준으로 다시 따져 본다.

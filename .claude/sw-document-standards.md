# 설계·산출물 문서 가이드

> 이 워크스페이스의 설계 문서 세트와 작성 순서를 정한다.

---

## 1. 근거

| 근거 | 이 가이드에 반영한 것 |
|------|----------------------|
| ISO/IEC/IEEE 15289 | 정보 항목은 합치거나 저장소(이슈 트래커·git·CI)에 둘 수 있다. 기준은 "문서 개수"가 아니라 "정보가 존재하고 추적 가능한가"다 → 고정 세트 10개 + 대체 수단 |
| ISO/IEC/IEEE 29148 | 요구사항은 ID 를 갖고 검증 가능해야 한다 → B2 의 REQ·AC (R3) |
| ISO/IEC/IEEE 42010, ADR | 아키텍처 결정은 맥락·선택지·결정·결과로 남긴다 → A3 |
| ISO/IEC/IEEE 29119-3 | 시험 계획은 구현 전에 확정한다 → C7 테스트 전략 (게이트 C) |
| CBD SW개발 표준 산출물 관리 가이드 | Step ID (A1, B2, C3 …) 의 출처. 흡수한 산출물의 번호는 비워 둔다 |

## 2. 작성 규칙

| # | 규칙 | 내용 |
|---|------|------|
| R1 | **선행 문서 게이트** | "문서별 선행 조건" 표의 선행 필수 문서가 **확정(사용자 승인)** 상태인지 확인한다. 없거나 초안이면 선행 문서부터 쓰자고 제안하고 멈춘다. 빈 부분을 추측으로 채워 진행하지 않는다. |
| R2 | **한 번에 한 문서** | 작성 → 사용자 검토 → 확정 후 다음 문서로 간다. 여러 문서를 한 번에 초안으로 쏟아내지 않는다. (A1·A3 갱신은 예외, R5) |
| R3 | **추적 ID** | 선행 문서의 ID를 후행 문서가 참조한다. 접두어: `REQ-`(요구사항) `NFR-`(비기능) `AC-`(인수 조건) `SCR-`(화면) `DEC-`(결정·ADR) `ISS-`(미결·위험). 테이블은 테이블명, 엔드포인트는 `METHOD /path` 가 ID 다. 테스트 이름·PR 에 REQ ID 를 넣어 추적표를 대신한다. 이 목록에 없는 접두어·번호(`G1`, `BR-1` 등)는 만들지 않는다. 참조될 일이 없는 표 행에는 ID 를 붙이지 않는다.<br>**읽기 쉽게**: 모든 문서 머리말에 ID 범례 한 줄을 둔다. 문장 속에서 ID 를 참조할 때는 `DEC-007(부가세 포함 가격)` 처럼 짧은 한글 설명을 붙인다. 표에서 같은 행이 내용을 설명하면 ID 만 써도 된다. |
| R4 | **역류는 선행 문서부터** | 후행 문서를 쓰다 선행 문서의 수정이 필요해지면, 선행 문서를 먼저 고치고 사용자 확인 후 돌아온다. 후행 문서에서 조용히 다르게 정하지 않는다. |
| R5 | **계속 갱신 문서** | A1 은 다른 문서의 상태가 바뀔 때마다, A3 는 결정·미결이 생길 때마다 갱신한다. 둘은 다른 문서의 선행 게이트가 아니다. |
| R6 | **고정 세트 밖의 파일 금지** | 고정 문서 세트에 없는 문서를 만들지 않는다. 필요해 보이면 먼저 기존 문서의 절로 넣을 수 있는지 보고, 그래도 필요하면 사용자에게 제안만 한다(승인 전 생성 금지). |
| R7 | **사용자 결정 영역은 확정하지 않는다** | 사업 정책, UI·디자인, 가격 등 사용자가 결정할 사항은 선택지와 근거만 제시하고 A3 에 ISS 로 올린다. |
| R8 | **기존 자산 우선** | 코딩 표준·보안·API 규칙은 새로 쓰지 않고 워크스페이스 `.claude/principles/` 와 코드 저장소의 규칙을 참조한다. |

| Step | 문서 | 파일 | 흡수한 표준 산출물 |

| C4 | API 설계서 | `C4-api-design.md` | 인터페이스 설계서 |
| C5 | 화면 설계서 | `C5-screen-design.md` | 사용자 인터페이스 설계서, 디자인 시스템 |
| C7 | 테스트 전략 | `C7-test-strategy.md` | 총괄 시험 계획서 (1장 분량) |
| C8 | 배포·운영 문서 | `C8-deployment.md` | 배포 계획·절차서, 운영 절차서(Runbook) |

**만들지 않는 표준 산출물과 대체 수단**

| 표준 산출물 | 대체 수단 |
|-------------|-----------|
| 수행계획서·WBS, 품질보증·형상관리 계획서 | 이슈 트래커, git 브랜치 전략 |
| 요구사항 추적표 | REQ ID 를 테스트 이름·PR 에 기재 |
| 프로그램(모듈) 설계서 | 코드 + 필요한 곳만 C1 의 다이어그램 |
| 코딩 표준 | `.claude/principles/` + 코드 저장소 `CLAUDE.md`·규칙 |
| 단위·통합·시스템·인수 시험 케이스·결과서 | 자동화 테스트 + CI 결과 |
| 결함 관리대장, 변경 요청서 | 이슈 트래커 |
| 사용자·운영자 매뉴얼 | 만들지 않음 (필요해지면 R6 절차로 제안) |
| 릴리스 노트 | 코드 저장소 `CHANGELOG.md` |
| 장애 보고서(포스트모템) | 이슈 트래커 |
| 완료 보고서, 테일러링 결과서, 단계별 검토 결과서 | 만들지 않음 |

## 4. 작성 순서

```
A. 착수   A1 산출물 관리대장(초안) → A2 PRD → A1 기능 분할 확정      A3 결정·이슈 기록은 전 기간 🔁
                     ║ 게이트 A: A2 확정
B. 분석   B2 요구사항 정의서 (기능별)
                     ║ 게이트 B: 해당 기능 B2 확정
C. 설계   C1 아키텍처 → C7 테스트 전략 → C3 DB → C4 API → C5 화면 → C8 배포·운영
                     ║ 게이트 C: 구현 착수 전 C1·C7 확정, 해당 기능의 C3·C4 확정
구현 이후  별도 문서 없음 — 테스트 코드·CI·CHANGELOG 로 증빙. C8 은 첫 배포 전에 확정.
```

## 5. 문서별 선행 조건과 완료 기준

| Step | 문서 | 선행 필수 (확정돼 있어야 함) | 완료(확정) 기준 |
|------|------|------------------------------|-----------------|
| A1 | 산출물 관리대장 | — | A2 확정 후 기능 분할에 사용자가 동의 |
| A2 | PRD | — | 목표·대상 사용자·범위(범위 밖 포함)·Phase·공통 NFR 승인 |
| A3 | 결정·이슈 기록 | — | 확정 상태 없음. 항상 `작성중` 🔁 |
| B2 | 요구사항 정의서 | A2 | 모든 REQ 가 검증 가능한 문장이고 AC 를 가지며, 필요한 화면(SCR)이 나열됨 |
| C1 | 아키텍처 설계서 | A2, 첫 기능 B2 | 기술 스택·구성·보안 모델이 DEC(ADR)로 기록·승인 |
| C7 | 테스트 전략 | C1 | 테스트 수준·도구·CI 게이트·완료 기준 합의 |
| C3 | DB 설계서 | B2(해당 기능), C1 | 해당 기능의 모든 REQ 데이터가 저장 위치를 가짐 |
| C4 | API 설계서 | B2(해당 기능), C1, C3 | 해당 기능의 모든 흐름이 API 로 구현 가능 |
| C5 | 화면 설계서 | B2(해당 기능의 SCR), C4 | 해당 SCR 모두 사용 API 매핑, 디자인 결정은 사용자 확인 |
| C8 | 배포·운영 문서 | C1 | 배포·**롤백** 절차, 비밀정보 관리, 장애 대응 순서가 있음 |

## 6. 기능 단위 반복

1. **공통 기반 먼저 (한 번)**: A1 초안 → A2 → A1 확정 → 첫 기능 B2 → C1 → C7
2. **기능마다 반복**: B2-<feature> → C3 에 누적 → C4 에 누적 → C5 에 해당 화면 추가 → 구현
3. **반복마다 갱신**: A1 상태, A3 결정·이슈
4. **첫 배포 전**: C8 확정

기능 안에서의 순서(요구사항 → DB → API → 화면 → 구현)는 바꾸지 않는다.

## 7. 매 문서 작성 시 체크리스트

- [ ] 고정 문서 세트에 있는 파일인가? (R6)
- [ ] 선행 필수 문서가 확정 상태인가? (R1)
- [ ] 선행 문서의 ID를 참조했고, 새 ID를 부여했는가? 머리말에 ID 범례가 있고, 문장 속 ID 에 한글 설명을 붙였는가? (R3)
- [ ] 사용자가 결정할 항목을 임의로 확정하지 않고 ISS 로 올렸는가? (R7)
- [ ] 확정 후 A1 상태와 A3 를 갱신했는가? (R5)
- [ ] 다음에 쓸 문서가 무엇인지 사용자에게 알렸는가?
